## Unreleased — 2026-08-01

- **`references/aos-integration.md` §1.1 — `subject` is not an instance key** (docs only; no code or
  behavior change). Mirrors intenttree **DI-283** into the writeback-envelope contract this repo owns,
  because that is what PF-3's phase-close-hook author will read — the warning previously existed only
  in `itt link report --help` and `intenttree/docs/DATA_MODEL.md`, which they would never open.
  - **The hazard:** PF-2 (`intenttree` PR #9, `5bf3f1b`) shipped `delivery_report` link identity as
    `external_id = report:<route>:<subject>`, upserted **refresh-in-place**. The envelope's `subject`
    is `report.subject or report.project` — repo/program/feature-level, with **no per-instance
    discriminator** (`delivery_report.py:1391`). Collapsing is correct for `feature` (one per feature)
    and `dossier` (a living record, regenerated by design), but for the routes that **recur** —
    `phase` at every phase boundary, `program`/`readiness` per milestone and per go/no-go — each new
    report would silently overwrite the previous one's link.
  - **Caller guidance:** for `phase`/`program`/`readiness`, make the instance unique — fold the phase,
    milestone, or decision into `subject`, reuse the envelope's existing `revision` field
    (`:1392`), or pass an explicit `itt link report --ref`.
  - **Ordering constraint recorded:** whether the contract should *enforce* route-aware identity is
    PF-3's **OQ-5**, and it must be settled before the C3 phase-close hook ships — a later identity
    change silently re-buckets rows already written. §2 gains a pointer so anyone reading the
    "never write" posture note (now being actuated by PF-3 C2/C3) is sent to §1.1 first.
  - Registered as a blocking open question in the PF-3 plan, PRD, and design spec §7.1.

## 0.1.0 — 2026-07-23

Initial release. Unified, route-discriminated report skill that **replaces `feature-report`**.

- **Routes:** `feature` (retrospective single feature — absorbs `feature-report`) plus
  `program` / `phase` / `readiness` (forward-looking, multi-item).
- **Handoffs:** every open forward-route item carries a copyable agent handoff — absolute repo,
  existence-checked paths, grep-verified requirement IDs, blocking gates, tracker node, and a
  paste-ready prompt. Validation is blocking: `deferred` needs a `trigger`, `blocked_external` needs
  `command: null`, `repo` must be absolute.
- **Honesty mechanism:** every vital cites `measured_by`; `corrections[]` is first-class; evidence
  and handoff paths are existence-checked when the repo is present; `verified_by` distinguishes
  self / delegated / unverified claims.
- **Feature-route enhancements** (the recommended `feature-report` changes, landed here):
  handoff-shaped `followups[]`, optional `domains[]`, light theme, per-`<code>` copy buttons,
  existence-checked evidence paths.
- **Visuals:** activity flowsheet + two-track ladder from declarative data; inline SVG flows/metrics;
  screenshots and clearly-labelled generated illustrations with recorded provider.
- **Theming:** four-block token system (`:root`, dark media query, explicit `data-theme`) with a
  viewer toggle that wins over the media query.
- **AOS:** `export` writeback envelope (skillmeat/intenttree/meatywiki/ccdash) and IntentTree tracker
  linking. Deterministic and offline throughout.
