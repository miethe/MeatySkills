# Native routing intent writer

`appendNativeIntent(envelope, {log_path})` is the canonical-ledger consumer for a native hook's already bounded routing projection. The CLI form is `node log-cli.js --native-intent - [--log-path <path>] < envelope.json`.

The envelope must contain exactly one `routing_log` decision with a stable native task identity (`native:<session-length>:<session-id>:<tool-use-id-length>:<tool-use-id>`), chosen logical provider `codex`, intended model, and routing record with matching provider/model plus explicit effort. The writer projects these allowlisted values and a fixed reason into the existing schema-v2 decision entry. It always writes realization fields as null/unconfirmed. Prompt, message, response, transcript path, cwd, and arbitrary fields are never copied. The caller must identify the logical Codex route; the writer does not infer account or actual backend from a native tool name or model pin.

The canonical JSONL ledger is the only deduplication authority. Under the ledger's adjacent advisory-lock file, a repeated event key with the same chosen provider/model/effort returns `duplicate` without appending; the same key with different intent returns a conflict. Other canonical writer paths share this lock, so ordinary decision, realization, and batch writes serialize with native intent writes. Existing rows are parsed strictly before any append; a malformed line or a final line without a newline refuses the write. A failed append does not create a separate dedup marker, so a valid retry can proceed.

The implementation requires Python 3 with POSIX `fcntl.flock`. The lock file is a crash-released mutex, not a second event registry. Deploy the helper beside `audit-log.js`; if the runtime cannot execute the helper, the writer fails closed. The native CLI reads at most 8 KiB of stdin and bounds the helper wait to two seconds; a timeout can be retried safely because the ledger is rechecked under lock. The CLI emits only `{"status":"written"}` or `{"status":"duplicate"}` on success and a fixed error code on failure; it does not print a ledger row or raw input.

This records routing intent only. A native hook event is not measurement of which provider/account/backend served the child. Actual provider/model remain unknown until an independent realization receipt is attached through `appendRealization` with evidence.
